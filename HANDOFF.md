# Handoff

For whoever continues this fork (a person, or Codex / another coding agent). It says what this fork is, what changed, how to build and test on this Mac, what was never run on a camera, and what to do next. Read [docs/roadmap.md](docs/roadmap.md) for the plan and [docs/one-shot-start.md](docs/one-shot-start.md) for the first delivered change.

## The fork in one paragraph

[ahonn/GRKit](https://github.com/ahonn/GRKit) adds film looks, crops, date stamps, glow, and grain to RICOH GR III / IIIx / IV from the SD card, with no firmware change. We forked it (`origin` = `botnick/GRKU`, `upstream` = `ahonn/GRKit`, forked at upstream `920c1d9`, v1.5.1, 2026-11-07) to (1) load sooner, (2) reach the feature set of GRLife Pro, (3) widen the film library, (4) fold in the good work of the community forks and issues, all **without ever flashing the firmware**. The SD script setting of the camera is turned on once and stays on until the disable package turns it off, as upstream does.

## What this branch changes (`feat/one-shot-start`)

| File | Change |
| --- | --- |
| `runtime/installer.c` | `--start`, `--start-known`, `--start-try`: one process scans, posts to the mailbox, waits for the arrays, installs, posts the result, writes the files and the boot log. `make_plan` / `publish_plan` / `open_plan_tmp` split out of `scan`; `install_planned` split out of `install` so the retries of a not-ready camera do not re-run the relocation. `ARRAY_LEAD` is 2 (probe array, then mailbox). |
| `runtime/install_io.h` | `ram_cache` and `read_whole`: a start reads each card file once and keeps a copy under `/tmp/grku-cache`. `read_effect` uses it. |
| `runtime/install_plan.h` | `read_module` uses `read_whole`. |
| `runtime/install_status.h` | `STATUS_NO_PROCESS = 4`. |
| `crates/grku-core/src/abi.rs`, `runtime/abi.h` (generated) | `MAILBOX_*` fields. |
| `crates/grku-core/src/runtime/loader.rs` | `LOADER.TTL`: allocates `mb`, polls the mailbox and the files, posts `mb[13]` after the arrays, sends `INSTALL.SH` only as a 10 s watchdog, writes the status of a failed start. |
| `crates/grku-core/src/runtime/files.rs` | `SCAN.SH` runs the core once with `--start*` and leaves while the start lock exists; `GRKU/DIAG` diagnostics; `INSTALL.SH` is the fallback and checks the pid of the start. |
| `crates/grku-build/src/tests/snapshots/*` | regenerated. |
| tests | `loader.rs` unit tests, `packaging.rs` script shape tests, `abi.rs` field test. |
| docs | `docs/one-shot-start.md`, `docs/roadmap.md`, `docs/lut-sources.md`, `docs/community-survey.md`, `README.th.md`, this file. |

The web site (`web/`) and the modules are unchanged. A package built from this branch has the same files as a 1.5.1 package (`SCAN.SH`, `INSTALL.SH`, `LOADER.TTL`, `CORE.BIN`, modules, effects), so the site's "write to SD card" flow still applies once the site data is rebuilt from this branch.

## Film library, icons, and menu tiles (branch `feat/film-library`)

- `effects/` has 135 looks: the 21 of upstream, 83 fitted from Pat David's film emulation presets (CC BY-SA 4.0) and t3mujinpack (MIT), 18 from spektrafilm (CC BY-SA 4.0) and Spectral Film LUT (MIT), and 15 from the Fotufilm film profiles (CC BY-SA 4.0), 1 own look (Positive GRII), and 1 from the Imprint repository (GR2 Positive, Apache-2.0): CineStill 800T and 400D, Harman Phoenix 200, LomoChrome Purple, Turquoise, and Metropolis, Lomography Color 100, instax mini and wide, Agfachrome RSX II 50/100/200, Kodacolor 100, Pro 160NS, and Fujicolor F-64D. The Fotufilm renders come from the `fotufilm` CLI of [fotufilm-engine](https://github.com/DhaliwalX/fotufilm-engine) (Swift + Halide; the recipe of each render is `effects/sources/bake_fotufilm.sh`) on the level 8 HaldCLUT of `grku effects hald`, fitted with `--input srgb`. Grades: every kept fit is A or B except Phoenix 200 (C: the film's crossover is beyond the camera's matrix model; kept because the film is the most reviewed new stock of 2025). Not taken: Eterna 500 and Reala 500D (D), Eterna Vivid 500 and Aerochrome 1443 (duplicates of better fits), Infrared Color (generic, no brand).
- Every effect has an own-image icon (`icon: {"png": ...}`): a film box drawn after the real box, in the brand colors (Kodak yellow and red, Fuji green, Ilford black with the accent of each film, Polaroid spectrum, Vision3 can label colors), with Roboto Condensed Bold and Black from `crates/grku-core/assets`. `scripts/flap-icons.py embed` draws them from the `cover` fields (template, brand, name, number); `scripts/flap-icons.py sheet OUT.png` renders a review sheet. The script needs Pillow (`~/…/scratchpad/luts/venv` has it, or `python3 -m pip install pillow`). `scripts/golden.py build/effects-all` pins `effects/golden.json` after a change.
- The menu tiles are in color too: `scripts/menu-tiles.py write` draws the 48 module tiles of `modules/*/tiles` (the Golden Spiral and Dynamic Symmetry guides of upstream 1.5.2 included) (a film canister for Film Look, a landscape cropped to each ratio for Framing, the guide lines for Guides, an orange date stamp for Date Imprint, a street lamp at night with bloom or a red halation ring for Glow, a grainy picture for Grain, the viewfinder marks with a black outline) and the 4 host tiles of `crates/grku-core/assets/tiles` (GRK as a lens with a coating-colored ring in the ADJ toolbar, VER, MOD, MOD off), which `artwork.rs` now embeds instead of drawing text tiles. After a tile change: `menu-tiles.py write`, rebuild the modules (`rm build/modules/*.GRM` first; `grku module build` refuses an existing output), `cargo install` the CLI (the host tiles are embedded), and refresh the snapshot `GRKU_UPDATE_GENERATED=1 cargo test -p grku-build`. The former monochrome tiles are what `crates/grku-core/examples/module-icons.rs` draws, kept for reference.
- `positive-film-grii-v1` (Positive GRII) is the first look of this repository itself: a HaldCLUT on the Standard JPEG that `effects/sources/make_positive_grii.py` writes from parameters set by eye after the Positive Film setting of the GR II (deep blacks, hard curve around the midtones, warm cast fading to white, saturation around the luma, blues to teal, greens to olive, reds to orange), fitted with `grku effects import --input standard` (grade A, mean ΔE 0.84). To tune it: change the parameters (or pass `NAME=VALUE` trials), regenerate, re-import, and rerun the finish step (copy the fitted `effect.json`, set `cover` to RICOH / POSITIVE / GRII and the attribution, pin the LUT sha in `sources/manifest.json`). Saturation must stay a luma-preserving chroma scale: HSV saturation darkened colors and cost a grade.
- `im-gr2-positive-v1` (GR2 Positive) is the GR2 Positive Film LUT of the Imprint repository (luqie0106, Apache-2.0): a stylized GR II positive look from a few parameters (contrast +9%, saturation -6%, cool shadows, warm highlights), fitted at grade A. It is the second reading of the GR II look next to our Positive GRII (warm shadows); the camera test decides which one stays in the defaults. The search for a measured GR II Positive Film LUT found none in 2026-11: ColorReps publishes a free "Ricoh positive (inspired)" .cube measured from GR IV DNG-JPEG pairs (no license stated, fits the model at grade C only), RawPresets and Osiris sell presets, rilongbao needs a login.
- The box icons carry a film type stripe at the bottom: orange = color negative, sky blue = slide, gray = black-and-white, teal = motion picture, rose = instant (`KINDS` in `scripts/flap-icons.py`; `film_kind` reads it from the flags, the cover, and the attribution target). Kodak boxes show the red K mark.
- `scripts/card.py` writes a package to the card (`write ZIP`, `--first` adds the ModeSet files), swaps the effects of the card from the library ZIP (`effects LIBRARY.zip LIST.txt`, at most 40 ids), and shows what the card holds (`status`). The card is the mounted volume with a DCIM folder, in a reader or in a camera that shows its card as a USB drive. `cargo run -p grku-build --example decode-firmware -- fwdc248b.bin rtos.bin` writes the decoded RTOS section of a firmware file for strings, Ghidra, or REA.
- A package carries 40 effects (`MAX_COUNT` of the runtime; the camera lists 64 files). `effects/defaults.txt` names the 40 of the release packages, chosen from the 2026 popularity research in `docs/popular-films-2026.md` (retailer best-seller signals, surveys, emulation popularity; Kodak's 2026 renaming of Portra to Ektacolor Pro and T-Max to Ektapan is noted there). `python3 -I scripts/defaults.py build/effects-all build/effects-default` copies their GRF files for `grku package --effects`. `dist/GRKU-film-library.zip` has every GRF with `INDEX.txt` to copy into `GRKU/EFFECTS` on the card. A better way to pick is the site (`docs/roadmap.md`, section 5).

## Test on a camera

1. Build the package (above) or take `dist/GRKU-gr3.zip` (or `GRKU-gr3x.zip`, `GRKU-gr4.zip`), copy the contents of `SD_ROOT` to the card root. If the card already has GRKU, replace only `SCRIPT`.
2. Power on three times. Each time, time GRK in ADJ with a stopwatch.
3. Read `GRKU/BOOT.TXT`: the `load`, `scan 0`, `install 0` lines of each start (see one-shot-start.md). `GRKU/REPORT.TXT` says what loaded. `SCRIPT/GRKU/INSTALL.ERR`, if it exists, says which step stopped.
4. Create an empty `GRKU/DIAG`, power on, wait 20 s, power off, read `GRKU/DIAG.TXT`, delete `GRKU/DIAG`. The `read-core` block gives the read speed of the card file system and whether a second read is cheaper. The `mounts` block gives the mount of `/media/storage1` and its options. This decides Phase 2.
5. If GRK does not appear within 30 s: power off, remove the card, and read the three files above. The fallbacks mean the most likely failure is a compile or syscall mistake in `--start`, which `INSTALL.ERR` and `BOOT.TXT` will name.
